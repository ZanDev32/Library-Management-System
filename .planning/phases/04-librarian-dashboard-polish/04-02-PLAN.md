# Phase 4: Librarian Dashboard & Polish - Plan 2 (Mobile Responsiveness & Performance)

## Goal
Ensure the app is fully responsive on mobile devices using the "Hidden Columns" strategy for tables, and review components for performance issues.

## Context
- **Responsive Strategy:** "Hidden Columns" for complex tables.
- **Target Performance:** Response times < 2s.

## Tasks

### 1. Implement Hidden Columns in Tables
**Description:** Use CSS media queries to hide less critical columns on mobile.
- **File:** `frontend/src/index.css` (or specific component CSS)
- **Action:**
  - Add a class like `.hide-on-mobile { display: none; }` for screens `< 768px`.
  - Apply this class to less important table headers (`<th>`) and cells (`<td>`) in:
    - `PendingRequestsTable.jsx` (hide "Tanggal Request")
    - `ActiveLoansTable.jsx` (hide "Batas Ambil")
    - `MyLoans.jsx` (hide "Tanggal Request" / "Tanggal")

### 2. Responsive Dashboard Layout
**Description:** Ensure the sidebar collapses or stacks on mobile.
- **File:** `frontend/src/pages/LibrarianDashboard.jsx` (and CSS)
- **Action:**
  - Use Flexbox/CSS Grid to stack the sidebar above or below the main content on mobile screens.

### 3. Performance Optimization Review
**Description:** Check frontend fetching logic.
- **File:** `frontend/src/pages/LibrarianDashboard.jsx`
- **Action:**
  - Ensure the `useEffect` fetching the requests has an empty dependency array or correct dependencies so it doesn't cause infinite loops.
  - Add basic error boundary or loading state styling (skeleton screens if desired, or simple spinner) to improve perceived performance.

## Verification
- `<manual>` Resize browser window to mobile width, verify tables hide specific columns and layout stacks nicely.
- `<manual>` Monitor network tab to ensure API calls are not duplicated and load reasonably fast.
