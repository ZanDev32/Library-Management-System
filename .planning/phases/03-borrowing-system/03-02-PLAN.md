# Phase 3: Borrowing System - Plan 2 (Backend APIs for Borrow & Approve)

## Goal
Implement the FastAPI endpoints for students to request books (and waitlist) and for librarians to approve or reject those requests.

## Context
- **Framework:** FastAPI.
- **Rules:** 
  - 2-step request (handled on frontend, backend just provides the endpoint to submit).
  - Librarian can batch approve/reject.
  - Rejection requires a reason.
  - Waitlist endpoint is needed.
  - Send email and in-app notification when status changes to Approved/Rejected.

## Tasks

### 1. Create Borrow Request Endpoint (Student)
**Description:** Endpoint for students to submit a request for an available book.
- **File:** `backend/app/api/endpoints/borrow.py`
- **Action:** Create `POST /api/borrow/request`.
- **Logic:**
  - Verify user is a student (JWT role check).
  - Check if `available_copies > 0`. If 0, return 400 (suggest waitlist).
  - Create `BorrowRequest` with status `PENDING`.
  - Do NOT decrement `available_copies` yet (only when approved/picked up, or decrement now and increment on reject? Let's decrement now to reserve it temporarily, or rely on active loans count. *Decision: decrement `available_copies` now to hold the reservation.*)

### 2. Create Waitlist Endpoint (Student)
**Description:** Endpoint for students to join the waitlist.
- **File:** `backend/app/api/endpoints/borrow.py`
- **Action:** Create `POST /api/borrow/waitlist`.
- **Logic:**
  - Verify user is a student.
  - Create `Waitlist` entry with status `WAITING`.

### 3. Create Approve/Reject Endpoint (Librarian)
**Description:** Endpoint to process pending requests.
- **File:** `backend/app/api/endpoints/librarian_borrow.py`
- **Action:** Create `POST /api/librarian/requests/process`.
- **Payload:** List of objects `{"request_id": int, "action": "APPROVE" | "REJECT", "reason": "str (optional if approve)"}`
- **Logic:**
  - Verify user is a librarian (JWT role check).
  - Loop through payload.
  - If `APPROVE`: set status to `APPROVED`, `approval_date` to now, `due_date` to now + 14 days, `pickup_deadline` to now + 2 days.
  - If `REJECT`: check if `reason` is provided (fail if not). Set status to `REJECTED`, `rejection_reason` to reason. Increment `available_copies` back for the book.
  - Trigger Notification Service (Task 4) for each processed request.

### 4. Implement Notification Service Stub
**Description:** Basic service to mock email and in-app notifications.
- **File:** `backend/app/services/notification.py`
- **Action:** Create `send_status_update_notification(user_id, status, message)`.
- **Logic:** For MVP, just print/log the email content and perhaps save to a simple `Notification` table if one exists (or skip DB notification for now and just log).
