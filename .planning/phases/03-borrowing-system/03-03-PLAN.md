# Phase 3: Borrowing System - Plan 3 (Backend Returns & Overdue Jobs)

## Goal
Implement the FastAPI endpoints for returning books (via QR scan) and the scheduled jobs to calculate overdue statuses and send reminders.

## Context
- **Framework:** FastAPI.
- **Rules:**
  - Return is done via QR/Barcode scan by the librarian.
  - The scan endpoint receives a unique identifier (e.g., `BorrowRequest.id`).
  - Overdue calculation is automatic upon return scan.
  - Reminder pattern: H-1, H, H+3.

## Tasks

### 1. Create Return Scan Endpoint (Librarian)
**Description:** Endpoint to process a returned book via scanned code.
- **File:** `backend/app/api/endpoints/librarian_borrow.py`
- **Action:** Create `POST /api/librarian/returns/scan`.
- **Payload:** `{"loan_id": UUID}` (This represents the decoded QR code).
- **Logic:**
  - Verify user is a librarian.
  - Fetch `BorrowRequest` by ID. Ensure it is currently `APPROVED`.
  - Set status to `RETURNED`.
  - Set `return_date` to now.
  - Increment `available_copies` for the associated book.
  - Calculate if `return_date > due_date`. If so, log the late days (could store in a new field `days_late` on `BorrowRequest`).

### 2. Create Overdue Detection & Reminder Job
**Description:** A background job to find overdue or soon-to-be-due books and send notifications.
- **File:** `backend/app/jobs/overdue.py`
- **Action:** Create a function `check_and_send_reminders()`.
- **Logic:**
  - Query all `BorrowRequest` with status `APPROVED`.
  - Check `due_date`.
  - If `due_date` is tomorrow (H-1): Send "Due Soon" notification.
  - If `due_date` is today (H): Send "Due Today" notification.
  - If `due_date` was 3 days ago (H+3): Send "Overdue" notification.
  - Ensure we don't spam (track sent reminders in DB if needed, or rely on precise date matching).
  - Also check for `pickup_deadline`. If `approval_date` is set, `status == APPROVED`, and `now > pickup_deadline` (and book not picked up yet - we might need a `PICKED_UP` state or assume `approval_date` means they have it? *Correction*: The context said "Ada batas waktu (misal 2 hari) pengembilan buku setelah disetujui". This implies a new state `PICKED_UP` is needed to stop the pickup timer. Let's add that to the endpoint logic).

### 3. Add `PICKED_UP` State Endpoint (Librarian)
**Description:** Endpoint to mark a book as picked up by the student.
- **File:** `backend/app/api/endpoints/librarian_borrow.py`
- **Action:** Create `POST /api/librarian/requests/{loan_id}/pickup`.
- **Logic:**
  - Verify librarian.
  - Set `BorrowRequest` state to `PICKED_UP` (or set a `pickup_date` field).
  - The due date calculation starts/remains from approval date, but the 2-day auto-cancel stops.

### 4. Create Extension Request Endpoint (Student)
**Description:** Endpoint for student to request more time.
- **File:** `backend/app/api/endpoints/borrow.py`
- **Action:** Create `POST /api/borrow/extend`.
- **Logic:**
  - Verify student.
  - Create `ExtensionRequest` for an active loan.
